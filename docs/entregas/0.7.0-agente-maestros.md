# Entrega 0.7.0 — El agente sube también clientes y artículos (VFP → web)

## Qué incluye
- Web: `POST /api/v1/vfp/maestros` (misma clave que el resto). Recibe un .zip con `clientes` y/o `articulos` (+ `datos.dbc`), **suma los nuevos y actualiza los que cambiaron** por código. No borra nada y no pisa lo que agrega la web (cliente desactivado, EAN-13, DUN-14, SKU, bultos, control de stock). Los códigos de rubro, vendedor, provincia, etc. que falten se agregan como «(DEL VFP)» (igual que la migración). Decisión D-21 en `docs/decisiones-pendientes.md`.
- Agente: `FacturaWebAgente.ps1` ahora hace dos envíos —comprobantes (como antes) y clientes + artículos— cada uno solo si cambió algo desde el último (`ultimo_envio.txt` y `ultimo_envio_maestros.txt`). Instrucciones en `agente-windows/LEEME.md`.
- El próximo código de cliente de la web sigue al mayor del VFP.
- Pruebas: suma, actualización sin pisar lo de la web, sin cambios y API por HTTP (clave inválida = 401). Además el recorrido de navegador ahora siembra su propia sucursal, forma de pago y artículo (antes dependía de tener cargados los datos de OYS).

## Qué probar (usuario Master o Administrador)
1. Actualizar el agente en la PC del VFP (reemplazar `FacturaWebAgente.ps1`) y correrlo: tiene que decir «Clientes y artículos: listo: …».
2. Cambiar un cliente o un precio en el VFP, volver a correr el agente y verlo en la web (Maestros).
3. Mientras convivan los dos sistemas, **no editar en la web** los datos que el VFP también carga: el VFP los pisa en la próxima sincronización.

## Desplegar y revertir
Actualizar con GIT y **Sistema → Aplicar cambios** (sin migraciones nuevas). Revertir: volver al agente anterior (deja de mandar maestros).

## Qué falta
- **Web → VFP** (pedido de Hernán): que lo emitido en la web llegue al VFP (subdiario, iva, estadística, caja, cta. cte. y stock). Decidido: el agente baja lo pendiente a una carpeta de intercambio y un programa nuevo dentro del VFP lo importa (así el VFP mantiene sus índices). Falta escribir la cola de pendientes en la web, la bajada en el agente y el `.prg` de importación.
- No probado todavía en la PC con Windows (en el contenedor no hay PowerShell).
