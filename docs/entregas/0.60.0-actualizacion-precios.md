# 0.60.0 — Actualización de precios por filtro

Pedido de Hernán (21/11/2026): un actualizador como «Actualización de Precios» del VFP para **aumentar por inflación aunque el costo no cambie**.

## Qué incluye

- **Maestros → Actualización de precios** (`/articulos/actualizacion`, permiso `articulos.precios`: Administrador y Master).
  - Filtros desde/hasta: código (buscador + lupa), proveedor, rubro y subrubro. Vacío = sin límite. Solo artículos activos.
  - Qué: una lista (1, 2, 3 u oferta), todas las listas, el precio de costo, o todas las listas y el costo.
  - Cómo: coeficiente (1,10 = 10 % más), porcentaje (negativo baja) o monto fijo en pesos.
  - Redondeo hacia arriba como en Parámetros (se puede destildar).
  - **Vista previa** (cuántos cambian, cuántos pasan a manual, los que no se tocan y por qué, antes → después). Nada se graba hasta «Confirmar»;
    si algo cambió entre la vista previa y el confirmar, no se graba y pide revisar de nuevo.
  - **Últimas actualizaciones** con **Deshacer** la última vigente (después queda la anterior). Lo que alguien tocó después no se pisa.
- La pantalla de márgenes ahora se llama **Precios por margen** en el menú y las dos se enlazan entre sí.
- Decisiones D-144 (fórmulas y reglas), D-145 (convivencia con «Precio automático»), D-146 (registro y deshacer).

## Convivencia con «Precio automático» (D-145)

| Qué se actualiza | Artículo manual | Artículo automático |
|---|---|---|
| Una lista / todas las listas | se aplica la fórmula | se aplica y **pasa a manual** (o se deja afuera, a elección) |
| Precio de costo | cambia solo el costo | cambia el costo y las listas se recalculan con sus márgenes |
| Todas las listas y el costo | fórmula a todo | costo con la fórmula, listas con margen recalculadas, las demás con la fórmula |

## Qué probar (usuario Administrador)

1. Maestros → Actualización de precios. Rubro desde/hasta uno, «Una lista» → Lista 1, Porcentaje 10, «Ver cómo quedan».
2. Revisar la vista previa y confirmar. En la ficha de un artículo, el historial dice «Actualización masiva».
3. «Deshacer» en Últimas actualizaciones: vuelven los precios.
4. Probar «Precio de costo» con un artículo de precio automático: el costo sube y las listas se recalculan solas.

## Despliegue y reversión

GIT → `>_` como siempre; la migración 0049 (tabla `precios_actualizaciones` y tres columnas en `articulos_precios_historial`) se aplica sola.
Es aditiva: para volver atrás alcanza con la versión anterior del código. Una actualización equivocada se revierte con «Deshacer».
