# Entrega 0.6.0 — Agente de sincronización (VFP → web)

## Qué es
Mientras OYS sigue usando el VFP, la web tiene que ver también sus comprobantes (para el subdiario de IVA y el stock). El **agente** es un script de
PowerShell para Windows 10 (no instala nada) que, en la PC del VFP, **lee los DBF**, los comprime y los manda a la web por HTTPS con una clave. Es el agente
el que se conecta: no hay que abrir puertos en la red del cliente. Solo **lee** el VFP (copia los archivos a una carpeta temporal; no los modifica).

## Qué incluye
- **Web**: `GET /api/v1/ping` y `POST /api/v1/vfp/comprobantes` (sin sesión ni CSRF; clave en `Authorization: Bearer fwk_…` o `X-FW-Clave`).
  La clave se guarda con hash (no se puede recuperar) y se crea/revoca en **Sistema → Agente de sincronización** (permiso `agente.administrar`),
  donde también se ven los últimos envíos y cuándo la usó el agente por última vez.
- **Incremental**: la web suma solo los comprobantes que no tenía (clave tipo + letra + sucursal + número + fecha) con su IVA, renglones, caja y cuenta
  corriente. No borra ni pisa nada, ni toca lo que se emitió en la web. Repetir un envío no duplica. Probado con los datos reales de OYS: 3.371 leídos,
  0 nuevos; se borraron 5 comprobantes y el siguiente envío los volvió a traer con sus hijas, sin tocar el resto.
- **Agente** (`agente-windows/`): `FacturaWebAgente.ps1`, `config.ejemplo.json` y `LEEME.md` con la instalación paso a paso (Programador de tareas). Si no cambió
  nada desde el último envío no manda; si falla deja el motivo en `agente.log`. Exige https.
- **Quién manda (decidido)**: los **comprobantes los manda el VFP**; los clientes y artículos siguen cargándose por la migración (no los toca el agente).

## Qué probar
1. Sistema → Agente de sincronización → crear una clave y copiarla.
2. En la PC del VFP seguir `agente-windows/LEEME.md` (`-Probar` debe decir «Conexión correcta»).
3. Hacer un comprobante en el VFP, correr el agente y ver en la web: Sistema → Agente → Últimos envíos (1 nuevo) y Listados → Subdiario IVA ventas.

## Desplegar
Actualizar y **Sistema → Aplicar cambios** (migración `0013_agente.sql`). El `.htaccess` de `public/` pasa el encabezado `Authorization` a PHP.
Si la web está detrás de un límite de subida chico, el hosting puede rechazar el envío (el agente lo informa).

## Qué falta (lo que decidimos dejar para después)
- Sentido contrario (web → VFP): hoy los comprobantes que se emiten en la web no vuelven al VFP.
- Que el agente sincronice también clientes y artículos, y el stock del VFP.
- Envío por partes si el hosting limita el tamaño (hoy se manda todo junto, comprimido: los datos de OYS pesan 0,5 MB).
- Una versión sin PowerShell (programa instalable) si algún cliente lo necesita.
