# Entrega 0.28.0 — Un cambio llega a todos los clientes, y altas simples

Hernán vende el sistema a varios clientes: esta versión hace que **actualizar a todos sea publicar una vez** y que un cliente nuevo sea **un comando y una lista de pasos**.

## Qué incluye
- **La base se actualiza sola** (D-59): después de actualizar el código, el primer pedido aplica los cambios de base pendientes. Ya no hay que entrar a «Aplicar cambios» en cada cliente. Un candado evita que migren dos pedidos a la vez (el otro ve «Actualizando el sistema… unos segundos»). Si algo falla, el sistema **no se bloquea**: avisa al Master en Sistema y en `/salud`.
- **Sistema → Instalaciones** (solo Master): una lista de todos los clientes con «Revisar todas» (versión, cambios de base pendientes, días de licencia, si falló la actualización); las desactualizadas salen en rojo (D-61).
- **Canal `estable`** (D-61): todos los clientes siguen la misma rama; Hernán dice «publicá» y Dev Senior la mueve. Paso a paso en `docs/publicar-a-todos.md`.
- **Alta simple y genérica** (D-60): `php bin/alta-cliente.php --nombre=… --dominio=… --perfil=mostrador --salida=…` (o `--host`, `--cuit=pendiente`, `--pv`, `--rama`). Los **perfiles** `basico` y `mostrador` dejan encendidas las opciones típicas al instalar. `PASOS.md` ya trae la rama `estable`, el webhook y el alta en el panel de instalaciones.
- `/salud` suma `migracion_error` y `licencia_dias`.

## Qué hacer vos (una sola vez)
1. **Rama `estable`**: ya existe (apunta a esta versión una vez publicada). Para OYS: Ferozo → GIT → cambiar la rama a `estable` y activar el webhook de auto-despliegue (cargarlo en GitHub → Settings → Webhooks, evento *push*). Probalo primero en una instalación poco crítica.
2. En Sistema → Instalaciones, cargar cada cliente (nombre y dirección).

## Qué probar con qué usuario
- **Master**: Sistema → Instalaciones: agregar una instalación, «Revisar todas», quitarla. Administrador y Operador no ven el panel.
- **Después de la próxima publicación**: comprobar que el cliente quedó con la versión nueva y «Al día» sin haber entrado a Sistema.

## Desplegar
Esta versión se actualiza como siempre (GIT + «Aplicar cambios» por única vez; la migración `0030_instalaciones.sql` crea `sistema_estado` e `instalaciones`). **Desde la siguiente, ya no hace falta.** Revertir: código anterior.
