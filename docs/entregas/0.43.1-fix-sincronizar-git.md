# Entrega 0.43.1 — Arreglo de la sincronización de GIT en Ferozo (otra vez)

Sin cambios de funcionamiento. Desde 0.37.0 (PR #45, 21/11/2026 1:17) `bin/pruebas.sh` tenía tres renglones nuevos (recorridos de importación,
alta de clientes y compras). Ferozo le cambia los permisos a los `.sh` de `bin/`, así que GIT veía `pruebas.sh` como «modificado» en el servidor
y se negaba a sincronizar: todas las «Implementación Remota» y «Sincronizar GIT» fallaban y el sitio quedó en 0.32.

- `bin/pruebas.sh` vuelve a ser idéntico al del servidor (el de 0.32).
- Los recorridos nuevos se listan en `e2e/extras.js`, que corre al final de `e2e/cuenta-corriente.js` (`bin/pruebas.sh` sigue corriendo todo).
- `tests/ScriptsCongeladosTest.php` falla si alguien vuelve a tocar un `.sh` de `bin/` o agrega uno nuevo.

Actualizar: Ferozo → GIT → **Sincronizar GIT** (o Implementación Remota) en `/facturador_web/`. Pasa de 0.32 a 0.43.1 de una vez; las migraciones
0034, 0037, 0038 y 0041 se aplican solas al primer ingreso (si no, Sistema → Aplicar cambios).

Revertir: volver a la versión anterior en GIT de Ferozo no hace falta; si algo falla, avisar con la captura del error de GIT.
